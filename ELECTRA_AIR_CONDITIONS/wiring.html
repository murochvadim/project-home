Electra A/C — connection wiring

Two Electra GEMINI boards driven over one RS-485 bus by a single wired ESP32 + W5500 bridge. No Home Assistant, no cloud — control rides the Ethernet cable to MQTT and the dashboard's Air Conditions tab.

1 A/C units ↔ bridge (the RS-485 bus)

Both A/C boards share the same three wires — A, B, GND. They're told apart by the Modbus address set on each board's DIP.

2 Inside the bridge — board interconnections

W5500 on VSPI, the RS-485 transceiver on UART2. Every GPIO here is boot- & OTA-safe; the SPI half matches the proven kazir_15 board. RST on GPIO13 (a plain pin, not a boot strap), INT optional.

logic (SPI / UART) 3V3 / VCC GND A B Ethernet
  • Shared GND is mandatory — the A/C boards and the bridge must share a common ground, or RS-485 won't communicate reliably.
  • 120 Ω terminators go across A–B at the two physical ends of the bus (the two A/C units). Many RS-485 modules have a jumper for this.
  • Set each board's DIP to MODBUS mode with a unique address (1 and 2). Do not wire the board's CLK/OUT pins — those are RCW wall-remote mode only.
  • Module = "RS485 V2.07" auto-direction — it switches TX/RX itself, so there is no DE/RE (GPIO25 unused). Wire only VCC / GND / RXD / TXD / A / B, and jumper EN → VCC to enable.
  • ⚠ RXD/TXD are crossed + bench-verify. Wire module RXD → ESP32 TX (GPIO17) and TXD → ESP32 RX (GPIO16). The TXD/RXD silk on these clones is inconsistent — if there is no comms, swap the two (one orientation is always right).
  • Boot/OTA-safe pins. RST → GPIO13 (a plain pin — lets firmware hard-reset a wedged W5500). Never GPIO2/GPIO12/GPIO15/GPIO0 — boot straps (GPIO12 held high at boot = the board won't boot at all). INT → GPIO4 is optional (SPI is polled).
  • 3.3 V logic only — the ESP32 is not 5 V-tolerant. Use a 3.3 V RS-485 transceiver (MAX3485 / auto-dir), never a 5 V MAX485 without level-shifting; W5500 VCC = 3.3 V.
  • Wired only — no WiFi. MQTT, OTA and control all ride the Ethernet cable.
